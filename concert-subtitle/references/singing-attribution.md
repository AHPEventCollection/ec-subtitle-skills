# 多人歌曲的演唱归属

歌曲由多人演唱时，在完整歌词对齐后执行本流程，识别单人、句内接唱、多人齐唱及未确定部分。不限定人数、性别、组合或颜色，不用观众镜头推断演唱者。本阶段识别由执行者结合实际音画证据完成，脚本负责保存、校验和渲染结果，不是端到端声纹识别模型

## 建立参照

- 先区分“有几路声音”和“具体是谁”。声音可区分但身份未确认时使用本场稳定的匿名ID，不能凭音色猜实名
- 从本场已确认独唱或清晰单人句选参照，覆盖不同音高、力度和唱法；不要只用一处短音节代表整个人。身份映射使用可靠节目资料、连续音画或用户明确纠正
- 参考与目标均保留独立音频时间范围。画面只辅助判断持麦、口型和换人连续性；单张近景、服装颜色、镜头切换不单独确认实际发声
- 环境已有且本任务允许的声纹或声学工具可生成候选，相似度保留为候选证据；伴奏、和声、喊声、混响和音域变化可能改变匹配结果。没有该工具时沿用音画判断，不安装新模型，也不假称已经运行声纹识别

## 逐曲判断

1. 对照独唱参照，结合带前后文的连续音频与必要画面，区分单人领唱、重叠合唱、观众回应和无法判断的区间
2. 一条字幕可能含多名成员依次接唱，或个人句与合唱呼应交替。按原文短句分别记录，保留原有字幕起止与中文，不为了分色改轴或拆译文
3. 已确认一轮轮唱结构时，回查同曲其他相似轮次；固定句式、相邻句归属与演唱次序是排查线索，不自动复制身份，也不按成员人数平均分句。不同轮次可能调换顺序或变成合唱
4. 对“单人句＋齐唱回应”、短呼喊、转场第一句和最后一句重点检查。近景延迟、切向下一位、画外主唱和同屏多人不能直接触发颜色变化
5. 用户纠正只作用于明确范围，保存依据；可据此定位其他相似句再复核，不能把局部纠正无条件传播到整首歌或其他场次

结果使用稳定事件ID，保存在事件的`singing_parts`及分段`evidence`中的参照、定位和待确认记录。姓名、具体配色及本场参照留在单场目录，不写入Skill

## 事件字段与显示

`singing_parts`按日文顺序列出短句，`text`拼接必须逐字等于该事件去除首尾空白后的`source_text`，保留标点和句内空格。字段不含新起止时间；原有时间、中文、正文和事件数量保持不变

```json
"singing_parts": [
  {
    "text": "君の声",
    "mode": "solo",
    "status": "confirmed",
    "performer_ids": ["singer_a"],
    "color": "#52B8D8",
    "evidence": [{"basis": "continuous_av_review", "reference": "evidence/voice-notes.txt#event_001"}]
  },
  {"text": "（Hey!）", "mode": "group", "status": "candidate", "performer_ids": []}
]
```

- `mode`为`solo`、`group`或`unknown`；`solo`必须是一人，`group`包含合唱或重叠多人，可记录至少两名已知成员，也可留空表示成员未知；`unknown`不指定身份
- `status`为`candidate`或`confirmed`。`confirmed`须有真实的`audio_review`、`continuous_av_review`或`user_correction`依据及可定位记录；静态画面、结构推测或声学分数单独不足以确认。脚本只检查记录形式，不代替回听
- `color`为可选`#RRGGBB`。仅已确认单人使用其颜色，合唱、未知和候选保持日文默认白色；白色不是已确认合唱的证明。中文保持原样式
- 同一稳定ID在本场使用一致颜色；匿名ID映射成身份时核对整场，不丢掉原来的音频参照
- 确认归属不等于批准字幕。`validate_section.py`检查短句完整性、身份数量与证据字段；分段批准增加`--point singing_attribution`，在完整分段审查中完成，不另增加用户审核轮次
- 修改事件会使旧gate及批准哈希失效，重新校验受影响分段；`merge_concert_subtitles.py`和审核ASS共同消费这些字段，禁止手工改正式ASS绕开事件真相源

## 与MC的边界

稳定身份、证据来源和未知状态可以作为未来多人MC功能的设计基础。本版`singing_parts`只接受歌曲歌词，不支持自动MC说话人识别、抢话分离或自动重建话轮；MC继续使用现行复杂度评估与连续音画人工复核流程
